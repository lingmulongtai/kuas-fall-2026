# 2026年度 秋学期 履修ダッシュボード

工学部 機械電気システム工学科 2年 4セメスタの履修科目・時間割・週ごとの授業内容・成績評価・教材をまとめた静的ページ。
ローカルではビルド不要。公開時は配信用ファイルを `dist/` にまとめ、Vercelから配信する。背景写真はUnsplash、雨の描画は指定の外部 `raindrops.js` から読み込む。

## ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | 骨組みだけ。ヘッダー、5つのタブ、各画面の骨組み |
| `style.css` | 配色トークン（ライト／ダーク）とレイアウト |
| `app.js` | 科目データ、日本語/英語の文言、描画処理 |
| `effects.js` | カーソルに反応するバネの動き、雨の背景との接続 |
| `glass-materials.js` | Good Machinesの6プリセットと元の光学シェーダー |
| `glass-renderer.js` | DOMの形状とWebGL2を接続し、各画面のガラスを描く |
| `scripts/build.mjs` / `vercel.json` | 配信ファイルの生成とVercelのビルド設定 |
| `rain.html` | 参考コードの画像・Canvas・CSSと、外部 `raindrops.js` の読み込み |
| `handouts/` | 授業で配布された資料の画像と、機械製作実習の班別Timetable（PDF）。科目詳細から開く |

内容を直すときは `app.js` の `COURSES` 配列を編集する。日付を直すときは同ファイル上部の `DATES` を編集する。
出欠の実績は `ATTENDANCE` に基準日・発行時刻・原票の出席率と記号を記録する。`marks` は基準日までのコマ順で、`present`（○）・`late`（△）・`absent`（×）・`null`（原票の空欄）を区別する。今後の日付を欠席として追加しない。
試験・小テスト・持ち物は各科目の `marks` に、授業回（`n`）・日付（`date`）・曜日（`day`、0=月）のどれかで指定する。毎回なら `all:true`（中間試験の回は除く）。成績評価の項目と結びつけるときは `evals` に `mark` を付ける。
宿題の決まりは `hw`（`due` が `dayBefore` なら次の授業の前日23:59、`class` なら次の授業まで。`submit` は提出の有無）、その回に出た宿題は `tasks`（`date` 付き）に書く。期限は次の実際の授業日から計算する。
授業で聞いたことは `memos`（`date` を付けるとその日の授業にも表示）、範囲ごとの担当教員は `phases`、配布資料の画像は `handouts`（PDFは `pdf:true`）に書く。各回のゲストや進め方は `schedule` の4番目の要素（`showcase`・`format`）に入れる。
機械製作実習の班別の回は `schedule` の中の `TA(実習番号, 開始, 終了の目安, 場所, 機械の日本語, 英語, 全班同時か)` で書く。班の名前は `SHOP_GROUP`、場所の表記は `PLACES`。

## 機能

- **いまの授業** — 時間割の上に、日本時間の現在時刻・授業中の科目（残り時間と進み具合）・次の授業（開始までの時間）を表示する。ページを開いた時刻から始めて毎分更新し、別のタブから戻ったときもすぐ合わせる。端末のタイムゾーンが日本以外でも日本時間で判定する
- 時間割では今日の曜日・今の時限・授業中の科目（「授業中」）・今日の次の授業（「次の授業」）に印を付ける。カレンダーと科目詳細の授業計画でも、授業中の回に印を付ける。印は描き直さずに付け替えるので、開いている資料や折りたたみはそのまま
- **科目詳細を開いたときの科目** — 授業中ならその科目、授業の合間や放課後は次の授業の科目を開く。科目の上部にその科目の授業中の回か次回（日時・教室・残り時間）を出す。科目を手で選んだら、次に授業が切り替わるまではその科目のまま
- **機械製作実習（TA01）** — 第3〜14週は班別Timetableの TA01 の開始時刻・場所・機械を、時間割（今日以降で一番近い回）・カレンダー・授業計画・いまの授業に表示する。班別TimetableのPDFは科目詳細の「配布資料を開く」から、ページ内（PC）か新しいタブで開ける
- **ホーム** — 時間割（1〜6限×月〜金）、試験・予定（中間試験・小テスト・科目ごとの次の提出期限と宿題・持ち物や授業形式に注意する日。残り日数つき）、科目一覧、休講日、欠席の目安
- スマートフォンの時間割は「1日／1週間」を切り替え可能。1週間は月〜金を画面内に並べ、科目名と教室をコンパクトに表示する。科目をタップすると詳細へ移動。表示モードはlocalStorageに保存し、1日表示に戻ると選択していた曜日を引き継ぐ。PC・印刷では常に5曜日を表示する
- **出欠・必要な出席回数** — 登録済みの記録をもとに、ホームの科目名または科目詳細の「出欠を入力・修正」から各コマの出欠を記録する。必要な今後の出席回数を即座に再計算し、このブラウザーに自動保存する。別端末へ移すための書き出し・読み込みにも対応する
- **カレンダー** — 月曜〜日曜の実日付で、9/21〜1/24の18暦週を表示。前後の週・週の選択・日付入力・「今日」で移動。← → キーでも移動できる（入力欄の操作は妨げない）。スマートフォンは日付順の縦表示
- **科目詳細** — 授業メモ・宿題と提出のルール・概要・到達目標・全授業計画（日付つき。範囲ごとの担当教員、配布資料の画像）・評価・教材・履修条件
- **教材** — 購入が必要な教科書、参考書、指定なしの科目、買うときのメモ
- 中間試験・小テスト・PC持参・要確認の中間の節目を、ホーム・カレンダー・科目詳細の授業計画と成績評価に表示する。授業メモ・キャリアショーケースのゲスト・宿題と提出期限は、その日のカレンダーと授業計画にも出す
- 教室・配信情報を時間割、科目一覧、週別、科目詳細に表示。週別では各回の授業形態を優先し、オンデマンド回や対面科目の遠隔回には教室を表示しない
- 日本語 / English 切り替え
- **設定** — Apple Liquid Glass / Apple clear / Thick lens / Frosted / Plain lens / Prism の6種類を全画面へ適用。初期値は参照URLのPrism。テーマ・言語・背景・雨の操作をまとめ、ガラスの選択もlocalStorageへ保存する
- テーマ：自動（OS 設定に追従）／ライト／ダーク。選択は localStorage に保存される
- スマートフォンの時間割は今日の曜日（土日は月曜）を最初に表示する
- 背景写真：ライト用の明るい風景とダーク用の夜景・星空から、ページの再読み込みごとにランダムな順番で選ぶ。同じ写真の連続表示を避け、テーマごとの残り順序をlocalStorageに保存する
- 「背景を変える」で次の写真へ。「雨：オン／オフ」「雨を一時停止／再開」の選択も保存される
- 休講日は12/28・12/29・12/30・12/31・1/1を含め、1日ずつ表示する

## 背景写真

`app.js` の `WALLPAPERS` に、明暗それぞれ13枚・計26枚の写真ID・撮影者・Unsplashの写真ページをまとめている。
選んだ写真を `images.unsplash.com` から画面サイズと画素密度に合わせて取得する。縦横比を保ち、長辺3840px・約830万画素を上限とする。画面拡大や回転時には同じ写真の解像度・切り抜きを更新する。APIキー・外部スクリプトは不要。
Unsplash全体を毎回検索する方式ではなく、選定した写真の候補から切り替わる。

同じページ内のテーマ切り替えでは、各テーマで読み込んだ写真を再利用する。言語やタブの切り替えでは写真を変えない。写真の候補が増えたときには抽選順を更新する。
通信に失敗した場合は最大3枚まで試し、読み込めなければ通常の単色背景に戻る。写真の取得を待たずに時間割を操作できる。
写真は装飾として扱い、印刷には含めない。出典はページ下部に表示する。
ローカルストレージが無効な環境でも表示は可能だが、再読み込みをまたぐ重複防止は利用できない。

通常の写真には薄いぼかしと明暗別の色を重ねる。雨をオンにすると、背景には `blur(4px) brightness(.45)`、雨粒の屈折元には同じ写真の鮮明な画像を使う。Canvasは通常合成・不透明度 `.95` とし、同じ写真を二重に加算しない。

雨の描画には、指定された [raindrops.js](https://fyildiz1974.github.io/web/files/raindrops.js) を直接読み込む。水滴の発生・合流・流れ・屈折はこのスクリプトが描画し、独自の軽量版への置き換えは行わない。`rain.html` のアダプターが前景・背景の写真テクスチャ（ユニット2・3）だけを選択中の背景写真に差し替える。これにより、内蔵の赤青の街路写真が重ならず、雨粒も実際の風景を屈折する。シェーダーのアルファ合成式・雨粒マップ・屈折量・動きは変更しない。写真は表示範囲に合わせて中央を切り抜き、縦画面でも再切り抜きが起きないよう写真の比率の指定だけを合わせる。写真の読込完了時には両テクスチャを更新し、停止中は粒を進めずに最後のフレームだけ描き直す。初回の描画前は写真を表示し、黒いCanvasを見せない。CSSやカードの配色は変えない。

参考コードの `overflow: hidden` は `rain.html` 内だけに適用し、ダッシュボードのスクロールを維持する。雨は背景用iframeに置き、背景写真・カーソル位置・停止状態を接続する。iframeは背景写真の非同期読込を待たずページ初期化時に読み込む。選択写真が届くまでは寸法を保って非表示・停止し、子から選択写真と一致する読込完了通知を受けて表示する。背景切替中も同じiframeを保持して停止・非表示にし、古い写真の通知では表示しない。背景には安定した高さの `100lvh`（未対応環境では `100vh`）を使い、スマホのアドレスバーが伸縮しても雨の再初期化や写真の再取得をしない。配布コードにリサイズAPIがないため、回転・ウィンドウサイズ変更などで背景の実寸や描画密度が変わった場合だけiframeを作り直す。停止時は描画フレームを止め、WebGLの最後の画像を保持する。外部スクリプトの読み込み失敗やWebGLが使えない場合は通常の背景写真に戻る。外部配布元の内容や提供状況に依存する。

## ガラスと動き

[Good Machines Liquid Glass Lab](https://goodmachines.ai/lab/liquid-glass)の6プリセットを使用する。取得日：2026/11/03。数値、屈折・分散・frost・照明のGLSL、17タップのGaussian blurを保持し、画面サイズやUI形状に接続する部分を実装している。描画中も解像度を下げず、参照と同じ最大DPR 2で描く。元サイトの8形状という上限を超えるUIには、端末のuniform上限に応じた形状配列と階層別の描画passを使用する。

1つのWebGL2 contextが背景とガラスを描き、文字・入力・ボタンはネイティブDOMに残す。親カードと子の操作面は別passにして両方の縁を保つ。設定のサンプルも、素材ごとのdim・mergeを含む同じ値で描く。雨は隔離したiframeから描画済みbitmapを受け取り、ガラスの入力に使う。水滴のシミュレーションや雨の品質値は変更しない。

雨の表示・一時停止とUIのアニメーションは独立している。雨を止めても画面切替やボタンの動きは続く。OSの「動きを減らす」は尊重し、その場合はUIの動きを抑えて雨も静止する。非表示タブ・印刷中には継続描画を止める。透明度を抑える設定・高コントラスト設定・WebGL2非対応時はCSSの表示を使う。スマートフォン実機とSafariでの見た目・GPU負荷は別途確認が必要。

雨の参考：[窓に流れる雨の表現](https://kumonosu.net/css/610/)。指定の外部スクリプトを使用する。

## 出欠を自分で入力する

1. ホームの「出欠・必要な出席回数」で科目名を押す。または科目詳細で「出欠を入力・修正」を開く。
2. 日付・時限を確認し、「○ 出席」「△ 遅刻」「× 欠席」「未入力」を選ぶ。実習・演習は同日の各コマを別々に入力する。未来の授業は日本時間の当日から入力できる。
3. 必要な出席回数がその場で更新され、ブラウザーに保存される。入力を修正・取り消した場合も計算し直す。

入力は同じ端末・ブラウザーで再読込しても残る。GitHubや大学の出欠システムへは送信せず、端末間の自動同期はしない。「入力を書き出す」でバックアップを保存し、別端末の「入力を読み込む」で引き継ぐ。読み込みは現在の入力をファイル内容に置き換える。

保存が使えない場合は画面に表示し、画面内での計算と書き出しは継続できる。破損データや他学期のバックアップは自動適用しない。

### 計算と記録

- 原票は `ATTENDANCE` に保持し、入力は `kuas-fall-2026-attendance-v1` のlocalStorageへ日付・時限ごとの差分として保存する。授業番号の入れ替わりや同日の複数コマを混同しない。
- ○のみを出席に算入する。必要出席数は `ceil(全コマ数 × 2/3)`、今後必要数は `max(0, 必要出席数 − 出席○)`。
- 経過分は原票の経過コマ数と、最後に入力したコマまでの数の大きい方。残り回数は全コマ数から経過分を引く。途中の未入力は未入力のまま残し、現在日付だけで出席・欠席を補完しない。
- 入力後の出席率は `出席○ / 経過分`（表示は整数％切り捨て）。入力のない科目は原票の表示率を保つ。元の表示率は科目詳細でも確認できる。
- 必要数を満たした場合や、残りをすべて出席しても不足する場合を科目詳細に表示する。過去の未入力・遅刻の確認余地を残し、単位の取得可否は判定しない。QOLの全回出席・各回課題など独自条件は別途確認する。
- バックアップはversion・学期・原票基準日・科目・日付・時限・値を全件検証してから反映する。不正なファイルを選んでも現在の入力を保持する。
